## 2. 비용 방어 — 오늘의 가장 중요한 작업

### 2-1. 배포 첫날 상한이 없었다

`.env.local`의 테스트 값(`DAILY_USER_LIMIT=1000000`)이 그대로 프로덕션에 올라갔다.
발견 즉시 3/200으로 교체. **이론상 일일 지출 상한 1.35억 원 → 2.7만 원.**

이 사고에서 배운 것을 코드로 굳혔다 — `envLimit()`이 `Number.isFinite` 검증 후
기본값으로 떨어진다. 이전에는 `Number("오타") = NaN`이고 NaN 비교가 전부 false라
**환경변수 오타 하나로 모든 한도 검사가 조용히 통과**했다(에러도 안 났다).

### 2-2. 전역 이미지 캡 (`ebff927`)

`/api/variant`·`/api/hero`가 IP별 카운터만 보고 전역 상한 밖에 있었다. 비용은
**세션이 아니라 생성한 이미지 장수**에 비례하는데(세션 1건 = 변주 5장 + 착용샷),
전역 캡이 세션에만 걸려 있어 IP를 갈아끼우는 만큼 비용이 선형으로 늘었다.

모든 생성 경로가 `quota:image:<날짜>` 하나를 공유하게 바꿨다. **이 키가 하루 지출의
실질적 상한이다.**

### 2-3. 선차감 + 환불

기존은 `조회 → (수십 초 외부 API) → 증가`라 그 사이가 통째로 경쟁 조건 창이었다.
잔여 1회로 병렬 20발을 쏘면 전부 통과했다(curl 몇 줄이면 된다).

`reserve()`로 뒤집었다 — INCR로 먼저 올리고, 넘었으면 되돌린다. 생성 실패 시
`release()`로 환불해 "실패는 미차감" 규칙은 그대로다. 테스트로 굳혔다:
동시 25요청이 정확히 한도만큼만 통과.

### 2-4. 초대 게이트 (`3936424`)

**Gemini 이미지 생성은 무료 티어가 없다.** 호출 1건이 곧 실비다. 수요 검증이 끝나기
전까지 공개 생성을 열어둘 이유가 없어서, `INVITE_CODES`에 코드가 있으면 생성 4라우트가
403을 낸다. 비우면 게이트가 꺼진다.

게이트는 **업로드보다 앞에** 둔다. 사진을 다 올리게 한 뒤 "사실 못 만들어요"는 최악의
순서다. `GET /api/analyze`가 `inviteRequired`·`hasInvite`를 함께 돌려주고 툴 카드가
코드 입력을 먼저 보여준다.

`DAILY_IMAGE_LIMIT`도 200 → 30으로 내렸다(최악의 날 약 2천 원).

### 2-5. 모델 관련 정정

한때 "`gemini-2.5-flash-image`가 10/2 종료되니 갈아타야 한다"고 판단했으나 **틀렸다.**
이미 `gemini-3.1-flash-image`를 쓰고 있어 종료 대상이 아니다. Lite로 가면 원가가 절반
(~$0.067 → ~$0.0336)이지만 품질이 이 제품의 유일한 차별점이라 보류했다. 게이트가
켜져 있어 생성량이 거의 0이므로 장당 단가의 의미도 작다.

## 5. 에이전트 진단 8인

코드·보안·전략 4인 + 디자인 4인을 병렬로 투입했다. 발견 중 **코드로 직접 확인한 것만**
반영했다.

### 5-1. 실제 버그 3건

**착용샷이 시안과 다른 쉐입으로 생성됐다.** `requestHero`가 팁셋을 만든 옵션이 아니라

착용샷이 나왔다 — 조용히 틀린 산출물 + 쿼터 소모. `genOptionsRef`로 생성 시점 옵션을
고정했다.

**데스크톱 3열 그리드가 한 번도 적용된 적 없었다.** 미디어 쿼리가 기본 선언보다
**앞에** 있어 소스 순서로 졌다(1440px 실측 2열). 5종이 2+2+1로 깨져 "다섯 갈래 세트"가
레이아웃에서 파괴됐다. 한 줄 이동으로 고쳤다.

**시안 카드가 스크린리더에서 버튼이 아니었다.** `<button role="listitem">`이 암묵
button 역할을 덮어 `aria-pressed`가 무효였다. 핵심 상호작용(5종 중 고르기)이 보조기술에서
통째로 사라져 있었다. `<li>` 래핑으로 복구.

### 5-2. 이미 만들어 놓고 안 쓰던 자산

하나만 UI에 갔다. 그 배지마저 5장 중 4장에 붙어 정보가 아니라 벽지였다.

`brief`의 `difficulty`·`feasibilityNotes`는 한국어로 생성돼 **클라이언트 메모리까지
도착했는데 0글자로 렌더**됐다. 랜딩은 "재료 조합까지 함께 나와요"라고 약속하고 있었다.

→ 결과 화면에 **시술 정보 블록**을 만들어 난이도·조정 메모·검수 점수·심사평·미달 항목을
표시한다. 7~8월 내내 투자한 검수기가 화면에서 제값을 받는 지점이다.

## 6. 계정·DB·보관함 (`813e36a`, `5b872e8`)

### 6-1. 왜 로그인만 붙이지 않았나

로그인만 붙이면 빈 껍데기가 된다. 생성물이 어디에도 저장되지 않아서, 로그인해도
재방문 시 보여줄 "내 시안"이 0개다. **혜택 없이 진입 마찰만 늘린다.** 그래서 저장까지
함께 만들었다.

### 6-2. 인증

Auth.js v5 + 구글. 원칙은 "안 가진 것은 잃을 수 없다":

- **scope는 `openid email`만** — 이름·프로필 사진을 아예 안 받는다. 안 받은
  개인정보는 지킬 필요도 고지할 필요도 파기할 필요도 없다
- **구글 access/refresh 토큰 미저장** — 이 앱은 구글 API를 쓰지 않는다
- **JWT 세션 7일, 세션 테이블 없음** — 대신 "특정 사용자만 강제 로그아웃"이 불가능하다
  (유일한 수단은 `AUTH_SECRET` 교체이고 그러면 전원 로그아웃). 수백 명까지 감당 가능한
  트레이드오프로 보고 수명을 짧게 잡았다
- `auth()` 실패가 생성 라우트 500으로 번지지 않게 **동적 import + try/catch** —
  로그인은 편의 기능이고 생성은 핵심 기능이다

### 6-3. 쿼터 3겹 — IP 한도를 지우지 않았다

로그인을 붙였다고 IP 한도를 지우는 것이 흔한 실수다. **구글 계정은 무료로 무제한
생성된다.** 계정 한도만 두면 계정을 갈아끼우는 만큼 뚫리고 그게 그대로 카드값이 된다.

| 층 | 키 | 막는 것 |
|---|---|---|
| 1 | `quota:user:u:<sub>:<날짜>` | 정상 사용자의 과다 사용 |
| 2 | `quota:ipday:<ip>:<날짜>` | 계정 갈아끼우기 |
| 3 | `quota:image:<날짜>` | 하루 지출의 절대 상한 |

`lib/quota.ts`는 파라미터 이름만 `ip` → `subject`로 바뀌었고 `reserve` 로직은 무변경.
라우트는 `quotaSubject(req)` 하나만 부르므로 나중에 판정 기준이 또 바뀌어도 한 곳만 고친다.

### 6-4. 저장소를 둘로 나눈 이유

| 저장소 | 담는 것 | 성격 |
|---|---|---|
| Upstash Redis | 일일 쿼터, 지표 | 사라져도 됨 (자정 자동 소멸) |
| Neon Postgres | 계정, 보관함 메타 | 사라지면 안 됨 |
| Vercel Blob (비공개) | 이미지 실체 | base64 한 장 300~800KB |

이미지를 Postgres에 넣으면 무료 0.5GB가 **600장**에 찬다. 경로만 DB에 두고 실체는
오브젝트 스토리지에.

ORM은 안 썼다. 테이블 2개에 쿼리 10개 남짓이라 마이그레이션 도구와 스키마 DSL을
들이는 비용이 얻는 것보다 크다. 모든 쿼리는 태그드 템플릿(`` sql`...` ``)이라 값이
자동 파라미터화된다.

### 6-5. 서명 URL — 막혔다가 푼 지점

비공개 Blob이라 읽을 때마다 서명 URL이 필요하다. 처음엔 사용자 폴더로 스코프된 토큰을
쓰려 했으나 실패했다:

```
Vercel Blob: pathname cannot contain glob characters.
```

위임 토큰의 `pathname`은 `"*"`(전체) 또는 구체 경로만 받는다. 항목마다 토큰을 발급하면
목록 1회에 최대 60번 왕복이므로, **전체 스코프 토큰 1개를 발급해 개별 URL을 파생**시킨다.

전체 스코프여도 안전한 근거를 실측했다 — 위임 토큰은 서버 밖으로 나가지 않고,
클라이언트에 가는 것은 경로마다 따로 서명된 URL이다:

```
A의 서명 URL로 A 접근:     200
A의 서명으로 B 접근 시도:  403   ← 서명이 경로에 바인딩됨
```

이 검증을 안 했으면 "안전하다"는 근거 없는 주장이었다.

### 6-6. 안전장치

- 업로드 성공 후 DB 기록이 실패하면 **업로드를 되돌려** 고아 blob을 남기지 않는다
- 삭제는 소유자 조건을 **쿼리 안에** 넣어 남의 것을 지울 수 없다 (실측 확인)
- 계정당 60장 상한 — 무료 티어를 지키는 선
- **DB가 없어도 앱은 돈다** — `getDb()`가 null이면 보관함만 비활성화되고 생성은 정상

## 7. 개인정보

`/privacy` 신설. 국외 이전 4곳(Google·Gemini·Vercel·Upstash)을 표로 명시했다.

**이 고지는 로그인과 무관하게 이미 미비 상태였다.** 사용자가 올린 사진이 이미지 생성
API를 통해 국외로 나가고 있었기 때문이다. 로그인이 계기가 됐을 뿐 원래 필요했다.

- 로그인 버튼 옆 동의 고지, 만 14세 이상 안내, 푸터 링크
- 탈퇴는 즉시 완전 삭제 (`on delete cascade`로 보관함도 함께)
- **업로드 원본 사진은 계속 저장하지 않는다** — 이 선 하나가 개인정보 리스크의 대부분을
  막고 있다. 나중에 저장 기능을 확장하더라도 대상은 "생성 결과물"로만 한정할 것

## 8. 보류한 것과 그 근거

### 구독 결제 — 만들지 않음 (에이전트 3인 만장일치)

| 이유 | 내용 |
|---|---|
| 수요 미확인 | 가격 버튼 클릭 수 0. 눌리는지 확인 전에 결제기를 만들면 질문 자체가 사라진다 |
| 법적 선행조건 | 한국 정기결제는 **사업자등록 필수** (현재 미보유). 집 주소·전화번호 공개 의무도 따라온다 |
| 경제성 | 월 4,900원은 구독자 **500명**이 넘어야 노동 대비 의미. 환불 문의 1건(10~20분)이 그 고객 몇 달치 이익 |
| 대안이 더 쌈 | 스마트스토어는 수수료 2.5% 더 내고 **개발 0시간**. 100명 기준 월 12,200원 차이 → 40~60시간 회수에 5년 |
| 순서 | 결제는 자동인데 콘텐츠 제작은 수동이라는 비대칭이 1인 구독 사업자를 무너뜨린다 |
| 신분 | **F-1** — 본인이 이미 "사업은 2027.8 귀국 후" 결론. 등록지가 아니라 "노동을 어디서 하느냐"가 기준이므로 수익 발생 전 OIS 확인 필요 |

**착수 트리거**: 클릭률 3% + 알림 이메일 10건, 또는 크몽 수동 판매 3건.

### 하지 않은 UI 작업

디자이너 P2(스페이싱 토큰 86곳 정착, 폰트 스택 순서), 데스크톱 2단 레이아웃, 5종 비교
모드, 전부 실패 시 쿼터 환불. 전부 "있으면 좋은" 범주라 검증 게이트 이후로 미뤘다.

## 9. 운영 안내

### 환경변수

| 이름 | 용도 | 없으면 |
|---|---|---|
| `INVITE_CODES` | 초대 코드(쉼표 구분) | **게이트 꺼짐** = 전체 공개 |
| `DAILY_USER_LIMIT` | 계정/IP당 세션 (기본 3) | 기본값 |
| `DAILY_IP_LIMIT` | IP당 세션 (기본 = USER×2) | 기본값 |
| `DAILY_IMAGE_LIMIT` | **하루 지출 상한** (현재 30) | 200 |
| `DAILY_TOTAL_LIMIT` | 전역 세션 (기본 200) | 기본값 |
| `AUTH_SECRET` | JWT 서명 | 로그인 불가 |
| `AUTH_GOOGLE_ID` / `_SECRET` | 구글 OAuth | 로그인 불가 |
| `DATABASE_URL` | Neon | 보관함만 비활성 |
| `BLOB_READ_WRITE_TOKEN` | Blob | 보관함만 비활성 |
| `GEMINI_MOCK=1` | **과금 없이 전 플로우 테스트** | 실제 호출 |

전부 없어도 앱은 뜬다. 기능이 하나씩 잠길 뿐이다.

### 자주 쓰는 명령

```bash
npm run db:setup     # db/schema.sql 적용 (멱등)
npm run db:verify    # 테이블·컬럼·행 수 확인
npm run db:smoke     # 실제 Neon+Blob 왕복 점검 (흔적 남기지 않음)

# 과금 0원으로 전 플로우 확인
GEMINI_MOCK=1 SEEDREAM_MOCK=1 npm run dev
```

### 게이트 여닫기

```bash
vercel env rm INVITE_CODES production --yes   # 전체 공개
# 되돌리려면 다시 add
```

코드를 고치는 게 아니라 환경변수 한 줄이다. 되돌리기도 한 줄.

## 10. 남은 것

**즉시 가능**
- 초대 코드로 실제 생성 1회 → 보관함 저장까지 (실비 몇백 원)

**다음 기능 후보**
- 생성 직후 자동 보관 (지금은 수동 저장)

- 로그인 사용자 한도 상향

## 부록: 오늘 반복해서 드러난 교훈

**1. 주석의 수치를 믿지 말고 실측할 것.** 대비 2건이 주석과 달랐고, 3열 그리드는
"있다고 적혀 있는데 한 번도 동작한 적 없었다".

**2. 계산해 놓고 버리는 데이터가 가장 아깝다.** 검수기 심사평, 시술 메모 — 둘 다
이미 만들어져 클라이언트까지 도착해 있었는데 렌더되지 않았다.

**3. 되돌리기 쉬운 것부터.** 오늘 바꾼 것 중 위험한 것은 전부 환경변수였다(한도, 게이트,
모델). 코드 변경은 테스트로 굳혔다.

**4. "안전하다"는 주장은 검증해야 주장이 된다.** 서명 URL 경로 바인딩 403이 그 예다.
