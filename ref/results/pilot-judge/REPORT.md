## 케이스 01이 가르쳐준 것 (반복 실행 로그)

1. **검수기의 눈은 정확하다**: 생성이 금속을 9~12팁에 도배한 것을 정확히 세고 "지정 수량 초과" 심사평까지 작성.
2. **판정 버그 발견·수정**: 초기 버전은 파츠 위반이 1점 감점에 그쳐 5/6으로 통과 → 파츠 위반을 물리 위반과 같은
   즉시 탈락 사유로 승격 (파츠 도배 = 1순위 품질 불만이므로).
3. **검수 이중 감점 수정**: partsMatch가 개수까지 자체 판단해 이중 탈락시키던 것 → "종류·배치만 판단, 개수는
   metalTipCount로만 보고"로 지시문 수정.
4. **분석 밀도 반영 수정**: 브리프가 "select tips" 같은 모호한 수량을 쓰던 것 → "원본의 파츠 밀도를 직접 세서
   명시적 개수로 반영"하도록 지시문 수정. 마지막 실행에서 원본(파츠 헤비 보드)을 "exactly eight tips"로 정확히
   반영하는 것 확인.
5. **운영 이슈**: 연속 호출 시 Gemini flash 분당 쿼터로 분석·검수 null 발생 → 양쪽에 1회 재시도(백오프) 추가.
   프로덕션에서는 호출 간격/지수 백오프 필요. 검수 실패 시에도 파이프라인은 best-of 폴백으로 결과를 반환(무응답 없음).

※ 케이스 01의 최종 PASS 확인은 쿼터 회복 후 `npx tsx scripts/pilot-judge.mts --only=01` 1회 재실행으로 완료할 것.

## 판정 규칙 (lib/judge.ts verdict)

- 즉시 탈락 3종: 물리 위반(매달림·부양) / AI 렌더 티 / **파츠 종류·배치·개수 위반** (개수 허용 오차 ±1)
- 나머지(베이스·팔레트·레터링): 6점 중 5점 이상 통과
- 전멸 시: 최고점 반환 + pass=false 플래그 (UI에서 "아쉬운 컷" 표시 또는 재생성 유도)
