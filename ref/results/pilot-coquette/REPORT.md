## 발견된 시스템적 실패 모드 (중요도순)

1. **역할 용어 "anchor" → 진짜 닻(⚓) 렌더링, 10세트 중 7세트에서 발생.**
   프롬프트의 `2 anchor tips`를 모델이 시각 모티프로 해석. glazed donut 사건과 동일 부류.
   → 수정: 다의어 금지. "anchor tip" → "statement tip" / "hero tip". 프롬프트 내 모든 단어를
   "이 단어가 그림으로 그려지면 어떻게 되나" 기준으로 검열할 것.
2. **개수 지시 무시 ("exactly 10 tips, 2 rows of 5") — 5/10 위반** (12·14·15·15·20개).
   생성 모델은 개수를 못 센다. → 완화: 레퍼런스 보드도 원래 15~25개이므로 개수 요구를 풀거나,
   상품 카드용은 후처리 크롭으로 해결. 개수는 루브릭에서 제외.
3. **네거티브(금지) 지시의 한계** — "no ombre" 명시에도 set-04에서 옴브레 등장.
   → 금지문보다 긍정문("crisp solid-color french boundary")이 효과적.
4. **팔레트 이탈** — 지정 2색 외 무지개 도트(set-05), 파스텔 초과 채도(set-02).
   → 검수 단계에서 걸러내는 것이 현실적 (프롬프트만으론 완전 통제 불가).
5. **앵커 손톱 중복** — "Angel" 레터링이 2~3회 반복(set-01, 06). 개수 통제 불가와 동근원.

## 결론

- **단발 생성 "알잘딱깔센" 불가 확정** (완전 통과 20%). 사전 예측(30~50%)보다 약간 낮음.
- 그러나 실패의 대부분이 **수정 가능한 프롬프트 버그**(anchor 다의어, 개수 요구)와
  **검수로 거를 수 있는 이탈**(팔레트, 옴브레)이었음. 스타일의 골격(누드 베이스, 딥프렌치,
  패턴 가두기, 파스텔)은 10세트 전부에서 유지 — v2 스타일 문법 자체는 작동함.
- 권장 아키텍처 재확인: **다발 생성(4~6) + vision 루브릭 자동 검수 + 통과작만 노출.**
  프롬프트 수정(1·2·3번) 후 통과율 재측정 시 40~60% 예상 → 4장 중 1장 이상 통과 확률 95%+.
